A shortcut to the session that needs you, find in a terminal, a tile that fills the window, a Claude Code of your choosing, and a conversation never runs twice.

## New

- **Go to the session that needs you** (Ctrl+Shift+Space, Cmd+Shift+Space on macOS). A window's title says how many of its sessions wait for an answer or a permission, and so does its taskbar button (on Windows with a badge, and it flashes when a session starts waiting unseen; on macOS the Dock icon bounces); the tray's tooltip says how many in all. The shortcut brings up the next one: in this window first, after the focused tile, then in the other windows, a collapsed one expanded.
- **Find in a terminal** (Ctrl+Shift+F). A find bar in the focused tile marks every match as you type, the scrollback included, and says which of how many you are at. Enter and Shift+Enter (or the arrows) go to the next and the previous one; Esc closes it and puts you back into the session.
- **Fill the window** (Ctrl+Shift+Z, or the new button in a tile's header). The focused tile takes the whole window for a while; the same again gives it back to all tiles. The layout does not change, and as soon as a tile is added, moved, expanded or closed, or another session is brought up, all tiles show again.
- **Which Claude Code runs** (Settings → _Claude Code_). Settings shows the `claude` reframe found on the PATH; _Choose…_ picks another one (two installs, say, or a PATH that differs for programs started from the Start menu), _Use the one on the PATH_ goes back. Sessions in WSL folders keep running their distribution's Claude Code.
- **Defaults for new sessions** (Settings): a model and a permission mode. _New session_ has them filled in, and they can be changed there as before.
- **Collapsed sessions drag** from the session list like any other, and land where they are dropped.

## Fixed

- **A session resumed in a terminal of your own** (`claude --resume <id>`) went unnoticed: _Resume_ on its tile, opening it from the session list or a workspace, and the next start of reframe each started it a second time, the same conversation running twice. Every resume now looks first whether the conversation runs outside reframe and asks to take it over, as with any other session. On reframe's own start the tile says it runs in another terminal, with _Take over_; the session list marks such sessions.
- **WSL**: a claude left running in WSL by a crash is now ended before its session resumes (it was resumed next to it). Reading a distribution's files, which starts a distribution that just stopped and takes seconds, no longer freezes reframe. And a registry entry whose process id another program has by now (Windows gives them out again; a distribution numbers its processes anew) no longer counts as a running claude: taking it over, or the orphan cleanup after a crash, could have ended that program.
- **Going back to an older reframe** after a newer one had saved its state lost every session, window and workspace, silently. A state file from a newer version is now left alone (reframe says so and quits); any other unusable one is set aside as `state.json.rejected-<time>` and the backup takes over.
- **After reframe's terminal host crashed** (it runs every claude), no session could be started until reframe was restarted. It is now started again, and the sessions it took with it say so, with _Resume_.
- **A window whose page crashed** stayed blank; it is loaded again, with its sessions as they were.
- **A start that fails** (no port for the hooks server, the state not writable) left a dead process holding the single-instance lock, so every later launch did nothing. It now says what happened and where the log is, and exits. Quitting can no longer hang on a session that does not end.
- **Start a new session here** marked the new session as used, so its next start reported a missing transcript instead of starting fresh. A worktree session no longer makes a worktree inside its worktree on a later start.
- **claude installed as a script shim** (npm's `cli.js` shim, pnpm, yarn) started a bare `node.exe`, or nothing; an unknown launcher in a path with a space did not start either. Both run as they should.
- **The session list** was asked for by every window every three seconds, forever, and each time reframe read every registry entry, every transcript's time and asked `wsl.exe`. The list is now sent when something changed: Claude Code's folder is watched, and WSL is looked at every 20 seconds while a list is shown, every minute otherwise.
- **Leftovers**: files dropped or pasted into sessions that had to be saved to the temp folder are removed after a week, and so are the hook settings of sessions reframe no longer has.
- **Hardening**: reframe's main process takes messages only from its own windows, a window ends only sessions it shows, and the hooks server answers a malformed path with 400. Electron 44.9.3 (a security advisory for 44.0 to 44.9.0: compromised eMudhra intermediate certificates), zod 4.6.7, koffi 3.3.3.

## Install

You need [Claude Code](https://claude.com/claude-code) installed and logged in: on Windows itself, or in WSL for sessions in WSL folders. The builds are not code-signed yet:

- **Windows**: `reframe-Setup-0.8.0.exe` installs for your user, without admin rights; installed copies update themselves. Or the portable `reframe-0.8.0-win-portable.zip` (right-click it → _Properties_ → _Unblock_ before unpacking). If SmartScreen warns, choose _More info_ → _Run anyway_. An installed and a portable reframe keep their own sessions and settings, but run the same Claude Code: a session one of them runs shows in the other as running elsewhere.
- **macOS** (Apple silicon): open the `.dmg` and drag reframe into Applications; the first time, right-click it → _Open_.
- **Linux**: the `.AppImage` (make it executable; it updates itself) or the `.deb`.

How to uninstall: [on the website](https://theycallmejuzou.github.io/reframe/download.html#uninstall). Windows releases are going to be signed through the SignPath Foundation: [code signing policy](https://theycallmejuzou.github.io/reframe/code-signing.html).
